# Gemini Project Instructions

Este es un proyecto activo. GitHub es la fuente de verdad del estado del código.

## Antes de realizar cualquier modificación

1. Lee completamente `PROJECT_CONTEXT.md`.
2. Lee completamente `TODO.md`.
3. Lee `README.md` y cualquier documentación técnica relevante.
4. Revisa la rama activa y los últimos commits.
5. Analiza el código actual antes de proponer o aplicar cambios.

`PROJECT_CONTEXT.md` contiene la memoria permanente del proyecto.
`TODO.md` contiene el estado de trabajo y los próximos pasos.

No asumas que una conversación anterior refleja el estado actual si contradice el código, los commits o estos documentos.

## Al trabajar

- Conserva la identidad PG Music y las decisiones documentadas.
- Prioriza estabilidad, velocidad y fluidez.
- No reviertas cambios existentes sin comprobar primero por qué fueron realizados.
- No reactives funciones heredadas de SimpMusic que estén documentadas como deshabilitadas.
- Verifica el impacto de cambios de licencias sobre el ecosistema PG.

## Después de un cambio importante

1. Comprueba que el proyecto compile y que las funciones afectadas sigan funcionando cuando sea posible.
2. Actualiza `TODO.md` con lo completado y lo pendiente.
3. Actualiza `PROJECT_CONTEXT.md` si cambió arquitectura, funcionamiento o una decisión importante.
4. Crea commits descriptivos que expliquen el cambio realizado.

Si existe una discrepancia entre estos documentos y el código actual, investiga los commits recientes antes de modificar nada y actualiza la documentación cuando corresponda.
